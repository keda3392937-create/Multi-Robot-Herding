# baseline 仿真实机围捕

入口是 `baseline_vicon_herding.py`。直接在 Python IDE 运行，不需要 CMD 启动器。
现有固件的六方向命令、SPD 调速、Vicon 坐标读取和通信模块继续使用。
需要现有 Vicon SDK，以及 numpy、scipy；实机入口不加载 matplotlib。

启动流程与 `twelve_car_3herder_chase.py` 一致：连接车辆 → 六方向并行短脉冲标定 →
进入控制。唯一区别是控制律换成 baseline 的凸包、视野、密度和追逐力。

## 初次运行

1. 电脑和小车连接 YAYA。在 Tracker 中启用 DataStream，并保持 `kedayaN` 命名。
2. 在文件顶部填写场地和笼子的 Vicon 世界坐标（见下一节），不要直接用文件里的示例坐标开跑。
3. 修改 `HERDER_IDS`、`EVADER_IDS`，支持 1～50 号且不能重复。默认 **18～25 为 8 辆 herder，
   1～17 为 17 辆 evader**，共 25 辆。
4. 先加 `--dry-run`：只连接 Vicon，打印场地/笼子的世界坐标与局部坐标、每辆车的局部坐标和
   到边界的距离，不连接小车、不标定、不发指令。
5. 确认无误后去掉 `--dry-run` 正式运行。六方向标定约 1 秒一个方向，25 辆约 7 秒，
   之后立即进入控制。

`ROBOT_DIAMETER_MM=150` 对应含全向轮的三角底盘最大外径；Vicon 刚体原点应接近底盘中心。
有偏心时用能包住车体的更大半径。

## 场地和笼子坐标（写死）

`FIELD_CORNERS_WORLD`、`CAGE_CORNERS_WORLD` 各填四个点，单位 mm，Vicon 世界坐标，
点的顺序随意。脚本会自动：

- 校验四个点能否构成矩形（边长、对角线、直角），不合法时直接报错退出，不会开始标定；
- 判断笼子贴的是场地的哪个角，并自动选择局部坐标系，让笼子落在局部坐标的“左上角”；
- 由笼子四个角算出实际边长，检查笼子是否贴着场地两边；笼子如果在场地中间会报错；
- 打印局部原点/轴向、笼子的世界与局部角点，方便和 Tracker 视图对照。

局部原点在场地一角，X 沿场地宽度、Y 沿场地高度；笼子固定为 `x=[0, Wc]`、`y=[H-Hc, H]`，
底边和右边各有一个居中开口（`CAGE_OPENING_MM`，默认 700 mm），朝向场地内部。
所以不需要关心输入的四个点从哪个角开始，也不需要在 Tracker 里摆角标。

`--dry-run` 还会逐车打印 `local=(x,y)` 和 `edge=...mm`：
`edge` 小于 `ROBOT_DIAMETER_MM/2` 的车会触发控制开始时的边界安全检查，
正式运行前会直接拒绝启动；小于 `MIN_START_CLEARANCE_MM`（默认 300 mm）的车只给出警告，
因为六方向标定脉冲可能把它推到边界上。

想把场地恢复成“按初始车位自动确定”的旧行为，把 `USE_FIXED_ARENA` 改成 `False`。
该模式仍使用 `FIELD_WIDTH_MM`、`FIELD_HEIGHT_MM`、`CAGE_WIDTH_RATIO`、`CAGE_HEIGHT_RATIO`。

## 六方向标定

与 `twelve_car_3herder_chase.py` 相同：每轮所有待标定车辆同时执行同一个方向，
`CALIBRATION_SPEED=255`、`CALIBRATION_MOVE_SEC=0.45`、停车后静置
`CALIBRATION_SETTLE_SEC=0.35`；Vicon 取脉冲前第一帧和脉冲中最后一帧的位置，
位移 ≥ `MIN_CALIBRATION_DISPLACEMENT_MM`（默认 30 mm）的方向记为有效。
6 个方向中至少 4 个有效、且方向覆盖空档不超过 150° 的车辆才进入控制。

标定期间不检查车辆间距、虚拟场地边界和 yaw 变化。这三点是旧版本“小车一开始就被大量排除”的
原因：旧参数是 110 PWM、0.30 秒脉冲，很多车单方向只走 20 mm 左右，低于 24 mm 阈值，
方向被逐个拒绝；再叠加 15° 的 yaw 门槛和场地边界判定，25 辆车最后只剩 2 个 herder。
现在脉冲改成满 PWM，位移通常在 100 mm 以上，和驱赶脚本的标定完全一致。

每次运行都重新标定（`RECALIBRATE_EVERY_RUN=True`），原因有两条：

- 旧缓存是在 110 PWM 下测的，与现在控制所用的 PWM 不匹配，速度换算会偏小；
- ESP32 固件在 TCP 空闲 **2.5 秒**后会主动断开客户端。如果一部分车复用缓存、在别人标定的
  十几秒里收不到任何指令，就会被固件断开，控制一开始就报 `TCP peer closed during PING`。

标定结果里的 `measured_speed_mm_s` 是 255 PWM 下的脉冲平均速度，碰撞过滤按 PWM 比例用它
估算实际速度，比从 110 PWM 外推准确。若某辆车 6 个方向都动不了，会打印每个方向的位移并退出，
这时应检查电机、电池、轮组或无线链路。

## 控制与安全

实机每帧使用 Vicon 的真实位置，对同一帧所有车计算力。模型保留每辆车的期望速度状态，
执行 `v += a*dt` 并限幅；不会用“实测静止”覆盖这个积分器，否则期望速度过不了电机死区。
实测速度只用于超速、无运动响应检测，以及滑行/碰撞预测。

长度按 `min(W,H)/80` 等比缩放，4 m 场地对应 herder 最大 **160 mm/s**、evader 最大
**240 mm/s**；它们是上限，实际速度随积分状态、PWM 标定和避碰变化。
herder/evader 加速度默认限制在 300/450 mm/s²。

发送前对实际六方向指令和 PWM 做物理检查：

- 所有可见车之间都检查车体尺寸，最小中心距离为 `ROBOT_DIAMETER_MM + BODY_GAP_MM`（默认 230 mm），
  低于该值时只让涉及的车辆停车；
- 先考虑实测速度下 0.25 秒的反应/滑行，再检查 1.2 秒预测时域内两条路径的连续最小距离；
- 标定速度按 PWM 比例换算，并使用 1.4 倍裕量；
- evader 在边界受困时，邻近 herder 优先尝试后退让位，不能安全执行则停车；
- 所有运动指令都不可行持续 30 秒会结束，提示调整车位或场地。

`ACTUAL_SPEED_LIMIT_FACTOR=2.5`：实测原始速度超过模型上限的 2.5 倍时整组停车。
Vicon 单帧跳变会让“两帧位移 ÷ 帧间隔”出现很大的瞬时值（例如真实 200 mm/s 时短间隔两帧
算出 300 mm/s），旧的 1.75 倍阈值在 25 辆车同时起步时过于敏感，容易把正常起步判成超速。

## 故障隔离

默认 `IGNORE_FAILED_CARS=True`，故障按单车隔离，herder 和 evader 使用相同规则：

- 启动时没有发现、TCP 连接失败、Vicon 不可见、标定不通过：跳过该车，其余继续；
- 运行中 TCP 写入/心跳失败，或持续发送运动指令却没有达到最小运动响应
  （默认 2 秒、15 mm/s）：停车并断开该车，余车继续，不重置正常车辆的速度状态；
- 单车 Vicon 姿态超过有效期：该车退出本次实验，其余继续，之后即使恢复也只作为障碍。

故障车从角色、追逐目标、凸包和捕获分母中剔除，算法按剩余车辆立即更新，退出原因写入日志。
仍然可见的故障车按实测位置避让；已经丢失定位的车保留最后位置并按最大速度×预测时域扩大避让范围。
少于 3 个有效 herder 或没有 evader 时结束。
Vicon 获取或一批指令耗时超过 0.2 秒时停车结束，避免发送过时决策。

捕获条件是所有当前有效 evader 的中心都处于留出车体余量的目标区域，连续保持 2 秒。

## 记录

校准文件为 `baseline_vicon_calibration.json`，当前标签是
`baseline-real-v3-fixed-4m-150mm`；场地尺寸、车体尺寸或标定策略改变后不会误用旧标签。
实验参数、初始车辆位置、场地/笼子世界坐标、参与车辆、标定数据、期望/实测速度、PWM、指令
和退出原因保存在 `relative_cage_runs/baseline/`。
`Ctrl+C` 停车，TCP、Vicon 及日志在退出时清理。

## 验证范围

测试覆盖与上传公式的数值对照、变速积分、不同角色迎面运动、路径交叉、边界、滑行、笼内车辆、
故障/丢失定位障碍、理想运动模型下的闭环围捕，以及本入口的固定坐标几何、四个场地角的
自动定向、六方向标定的接受/剔除逻辑。
这些是软件与理想模型验证，没有在真实小车上执行。有限预测、标定误差和制动误差可能影响避碰；
拥挤、无可行通道或原算法局部停滞也会影响捕获，不能保证任意初始队形零碰撞且必定捕获。
